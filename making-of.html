Making-of

Escape OS

Un escape game pédagogique en dix époques, des cartes perforées de 1965 à l’agent IA de 2026, écrit en HTML, CSS et JavaScript natifs. Le soin visuel avant tout : chaque époque est reconstituée « dans l’esprit », sans un seul logo, fond d’écran ni son d’origine.

  • 0dépendance
  • 0étape de build
  • 0fichier audio
  • 40 Kocompressés au premier chargement, hors polices
  • 10écrans chargés à la demande

Zéro dépendance, aucune étape de build

Des modules ES natifs servis tels quels. Chaque époque est un module chargé avec import() au moment du saut, avec sa feuille de style : le joueur ne télécharge que l’époque qu’il visite. Pendant qu’il joue, l’époque suivante se précharge en tâche de fond.

export function load(era) {
  return Promise.all([
    import(`../screens/${era.file}`),
    loadCss(`css/eras/${era.id}.css`),
  ]).then(([mod]) => mod.default);
}

Chaque écran respecte le même contrat : { id, era, year, mount(root, ctx) }, et mount renvoie sa fonction de nettoyage. Le contexte fournit le carnet, les indices, les sons et la fin d’époque : un écran n’est qu’un décor et un scénario posés sur trois composants partagés (terminal, fenêtres, gestes).

Le cadre qui se métamorphose

Le matériel autour de l’écran est dessiné en CSS : télétype, moniteur cathodique beige, écran plat, téléphone, puis plus rien en 2026. Pendant le saut, la position, la taille, les rayons et la couleur du cadre transitionnent ; l’écran garde sa résolution logique d’époque (640 × 480, 1024 × 768, 320 × 480) et il est mis à l’échelle d’un transform.

.scene.morphing > * {
  transition:
    left 1.15s, top 1.15s, width 1.15s, height 1.15s,
    border-radius 1.15s, background-color 1.15s, box-shadow 1.15s;
}

Effets cathodiques, en CSS seul

Lignes de balayage, vignettage, reflet du verre, scintillement très léger et extinction qui réduit l’image à une ligne puis à un point : aucun canvas, aucun shader. Le tout disparaît si le système demande moins d’animations.

.glass-fx {
  background:
    radial-gradient(ellipse, transparent 62%, rgb(0 0 0 / .5) 100%),
    repeating-linear-gradient(180deg, rgb(0 0 0 / .11) 0 1px, transparent 1px 3px);
}

@keyframes crt-off {
  45%  { transform: scale(1, .008);    filter: brightness(3.5); }
  75%  { transform: scale(.004, .008); filter: brightness(6); }
  100% { transform: scale(0, 0);       opacity: 0; }
}

Le compteur d’années

Un odomètre : chaque chiffre est une colonne de chiffres qui défile d’un seul transform. Les chiffres de droite font plus de tours, et un léger flou de mouvement accompagne la course.

.odometer.run .odo-strip {
  transform: translateY(calc(var(--steps) * -1em));
  transition: transform 1.7s cubic-bezier(.5, 0, .12, 1);
}

Des sons synthétisés

Cliquetis du télétype, bip du haut-parleur du PC, disquette qui gratte, carillons de démarrage, poignée de main d’un modem 56k, Wizz : tout est fabriqué en direct par Web Audio, à partir d’oscillateurs et de bruit filtré. Aucun fichier audio, et aucun son protégé.

dtmf(key) {
  const i = '123456789*0#'.indexOf(key);
  this.tone({ freq: [697, 770, 852, 941][Math.floor(i / 3)], hold: 0.12 });
  this.tone({ freq: [1209, 1336, 1477][i % 3], hold: 0.12 });
}

Pointer Events et FLIP

L’API Drag and Drop de HTML5 ne fonctionne pas au doigt : fenêtres, cartes perforées et glissière du téléphone reposent sur les Pointer Events, souris et tactile confondus. Les cartes se réordonnent avec la technique FLIP : on mesure, on change le DOM, puis on anime l’écart.

export function flip(elements, mutate) {
  const first = new Map(elements.map((el) => [el, el.getBoundingClientRect()]));
  mutate();
  for (const el of elements) {
    const a = first.get(el);
    const b = el.getBoundingClientRect();
    el.animate(
      [{ translate: `${a.left - b.left}px ${a.top - b.top}px` }, { translate: '0 0' }],
      { duration: 280, easing: 'cubic-bezier(.2, .7, .2, 1)' },
    );
  }
}

Le pincement du smartphone combine deux doigts, le pincement du pavé tactile (transmis comme une molette avec ctrlKey) et des boutons +/− de secours.

Du pixel art en SVG

Icônes et pointeurs (flèche, sablier) sont dessinés sur une petite grille puis convertis en chemins SVG nets à toute échelle, avec shape-rendering: crispEdges.

const HOURGLASS = pixelArt([13, 22], (p) => p.map(0, 0, [
  'KKKKKKKKKKKKK',
  'KWWWWWWWWWWWK',
  // …
]));
root.style.cursor = svgCursor(HOURGLASS, 6, 11, 'wait');

Accessible et jouable partout

  • Chaque geste a son alternative : clavier pour le glisser-déposer, flèches pour déplacer une fenêtre, boutons +/− pour le pincement, touche Entrée et commandes en pastilles sur mobile.
  • Sorties des terminaux annoncées aux lecteurs d’écran, fenêtres et boutons atteignables au clavier.
  • Mouvement réduit respecté : ni scintillement ni tremblement, sauts en simple fondu.
  • Conçu pour l’ordinateur, jouable au téléphone : HUD replié en barre basse, matériel simplifié.
